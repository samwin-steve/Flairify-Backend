# Three-minute Flairify demo

**0:00–0:25 — The problem**
“Shopping usually starts with a product. Flairify starts with what you already own. Share your wardrobe once. Find pieces that work with your life—and see the look on you.”
Show the light pink home page. Point out the **Demo data** label: all stock, stores and prices in this run are sample facts; photos are licensed examples.

**0:25–1:05 — Wardrobe first**
Start a private demo. Enter a name, clothing size M and EU shoe size 39. Choose whether to remember preferences. Show the optional reference-photo step and separate Google Photos authorization. Use **Explore with a sample wardrobe** for a deterministic presentation. Confirm all four garments. Explain that direct uploads are supported and, when Gemini is not configured, require manual review rather than fictitious detections. Continue to the stylist.

**1:05–1:55 — A real-life request**
Choose “Help me pack for Mumbai”: three working days, walking, ₹5,000. Show owned versus new items, the combined new-piece total, available size, sample store, supplied aisle/rack and delivery eligibility. Explain that each look checks an entire outfit, not just a compatible pair. Try “Something cheaper” and “Show another jacket.” Save a look. Show the wardrobe remains accessible.

**1:55–2:25 — Seeing possibilities honestly**
Choose “See it on me.” In an unconfigured demo, show the clear unavailable result in the fitting room; no generated output is fabricated. If real models and verified product images have been separately configured and tested, show the source/reference alongside the actual output, accept it, then request **Show in motion**. Refresh to demonstrate persistent job state. Explain that previews visualize style, not exact physical fit.

**2:25–2:45 — Experimental AR**
Open the 3D / AR lab. Rotate the explicitly labeled CC0 sample mannequin. Explain that personal reconstruction, rigging and garment fitting are separate unresolved tracks; the sample is not the customer. Unsupported devices retain normal 3D interaction.

**2:45–3:00 — Google Cloud and value**
“Cloud Run serves the responsive app, API and private worker. Firestore keeps customer state; private Storage holds photos; Cloud Tasks controls asynchronous work. Vertex provider adapters and BigQuery projections are configurable. The goal is useful purchases and more wear from clothes you already love.”
